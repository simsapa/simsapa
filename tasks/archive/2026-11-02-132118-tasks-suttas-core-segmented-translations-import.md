### 2.0 Footnote rendering and the footnote bar

**The usability requirements this group must meet** (PRD FR 36), on **every page with footnotes** — segmented records (SuttaCentral comments and, later, the suttas-core notes), the HTML suttas that already have footnotes (`kp3`–`kp9` Ṭhānissaro `span.fn`, 16 Nyanadipa pages `sup.footnote-reference`) and the library book chapters (58, `sup.footnote-reference`); all use `assets/templates/page.html` and the same footnote code:

1. A note appears in the bottom bar while its number is in view, and leaves when it scrolls out.
2. The note text in the bar can be selected and copied.
3. Sutta cross-links in a note work.
4. The bar respects the "show footnotes bar" setting (`show_bottom_footnotes`).

Find-bar matching and clean copied sutta text (numbers out of the text nodes) are a further benefit.

**Spec — stored form (FR 31).** A `sutta_comments.content_json` value in the new form is one or more elements, in `number` order:

```html
<span class='ssp-fn' data-n='2' data-w='6'>note HTML</span>
<span class='ssp-fn ssp-fn-editor' data-n='7'>[Editor's note] …</span>
```

`data-w` is absent for a whole-segment note. A value containing no `ssp-fn` element is a plain SuttaCentral comment. Encoding and parsing live in one module (`backend/src/footnotes.rs`), so the bootstrap writes exactly what the renderer reads.

**Spec — rendered markup (Rust).** For each note the segment text gets
`<span class='footnote-reference'><a href='#fn-<prefix>-<n>' id='fr-<prefix>-<n>'><n></a></span>` — the number **as text**, so HTML served outside the reader (`/sutta_html` and other API routes) still shows it. After the article, a list
`<section class='ssp-footnotes'><h2>Notes</h2><ol><li id='fn-<prefix>-<n>' value='<n>' class='…'>note HTML</li>…</ol></section>`.
`is_footnote_link()` already accepts an `<a href="#…">` inside `.footnote-reference`, and `get_footnote_content()` already returns an `<li>`'s inner HTML and strips `a[href^="#fr-"]` back-links. `<prefix>` makes ids unique per column: the record uid sanitised to `[a-z0-9-]`.

**Spec — markers in the reader (TS, FR 32a).** `normalise_footnote_markers(root)` in `src-ts/footnote_modal.ts`: for every `.fn a[href^="#"]` and `.footnote-reference a[href^="#"]` under `root` that `is_footnote_link()` accepts and that has no `data-n` yet, set `data-n` to its text with brackets stripped (`[1]` → `1`) and empty the text. Idempotent. CSS draws the number in brackets: `.fn a[data-n]::after, .footnote-reference a[data-n]::after { content: "[" attr(data-n) "]"; }` with superscript styling — `[1]`, `[2]` on every page with footnotes (the user's choice, for visibility). The brackets are never stored in `data-n`. `extract_footnote_number()` reads `data-n` first, then the text.

**Spec — numbering.** Notes in the new form keep their stored `data-n`. A plain SuttaCentral comment is numbered 1, 2, 3… in segment order within the record, and placed at the end of its segment.

**Spec — word index.** Count words **exactly as suttas-core does** (`src/segment/footnotes.ts`): the stored segment string split on `\s+`, empty tokens dropped, punctuation-only tokens counted, zero-based. All indexes in the 2026-10-31 data are in range under this rule. Insert after word `w`, **before** its trailing punctuation (`.,;:!?’”)—…`), so `disappeared:` → `disappeared²:`, and never inside an HTML tag (3 imported segments contain tags). A `w` past the last word goes at the end, logged at `warn` (it means the two sides disagree).

**Spec — the bar.** `update_display()` today rebuilds the whole bar with `innerHTML` on every change, which destroys a selection in it, and showing the bar reflows the page, which can change which markers are in view. It must instead keep one DOM item per visible note (keyed by footnote id), insert new items in number order, remove only items that left, attach link handlers to each new item once, and leave untouched items as they are. In multi-column pages, when more than one column has notes, an item's number is shown with its column label.

**Depends on:** nothing (works with SuttaCentral comments, HTML suttas and books already in the DB).

### 5.0 Ṭhānissaro import

**Spec — mapping.** Input: the uids the dhammatalks.org importer wrote (`… /en/thanissaro` with `content_json IS NULL`). The override file `assets/thanissaro-uid-overrides.toml` holds `[[override]] old = "…" new = "…" why = "…"`; an entry whose `new` is not a segmented `than` text is reported as an error line (not applied).
