### Findings from the codebase check (differences from the PRD)

1. **The commentary search filter would not hide the Ānandajoti pages.** All three search paths exclude commentaries only when the uid ends in `/cst` or `/opentipitaka` (`query_task.rs` ~l. 657 and ~l. 1132; `searcher.rs` ~l. 853 restricts `is_commentary` to sources `cst` and `opentipitaka`). `dhp21-32.att/en/anandajoti` would show with the setting off. FR 9 / FR 34 require a fix: exclude any `.att` / `.tik` uid whatever the source (task 1.0).
2. **Setting names.** The PRD says *include_commentary_in_search_results*; the code has `include_cst_commentary_in_search_results` and `include_cst_commentary_in_translations` (`app_settings.rs`), passed on as `include_cst_commentary`.
3. **`nyanadipa.rs` is no longer an HTML importer** (it now reads segment files). The `content_plain` pattern to follow is `sutta_html_to_plain_text()`, as in `dhammatalks_org.rs`.
4. **`bootstrap_cli` has no direct epub or zip dependency**, but `epub 2.1.5` and `zip` are already in `bootstrap_cli/Cargo.lock` through `simsapa_backend`. Adding `epub = "=2.1.5"` compiles nothing new, but it is still a manifest edit.
5. The existing `dhp*/en/anandajoti` verse records (26 of the 193 `anandajoti` rows) have `nikaya` `dhp`, empty `group_path`, and `sutta_range_*` set. The new importer runs after the CST import, so it can copy the columns from the `.att/en/opentipitaka` row as FR 27 says.
6. **No `cst:frag:` rows for the Dhammapada (PRD FR 5, corrected).** Each CST toc leaf matches one fragment of the same title, so `build_fragment_branches()` collapses it, and the leaf `cst:s0502a.att2.xml` opens `dhp21-32.att/pli/cst` directly. The node ids do not change, only their `sutta_uid`.
7. **Epub facts corrected in the PRD (FR 14, 15, 17).** The Conclusion is `039.html` (`038.html` is an empty `<h1>`). Note refs have nine span classes, some inside headings. Story `<h2>` classes vary. The `<h1>` splits English and Pāli with `<br/>`. The Conclusion's per-vagga counts use two phrasings.
8. **The column-bar dropdown stays as it is (PRD §6, decided).** It labels by author and edition only, so the two Ānandajoti entries of a vagga both read "anandajoti (en)", as the OpenTipitaka ones already do.
